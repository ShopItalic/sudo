P09: scroll from the Ring.

Four touch directions now produce standard Bluetooth HID mouse scrolling. Ring Controls chooses which directions are enabled and confirms the settings saved on the Ring.

Implementation and software verification. This task does not sign, publish, install, or flash P09. Scrolling in specific iPhone apps remains a physical acceptance step.

What the user controls

Swipe gestures starts Off. Turning it on reveals the four direction switches. The app uses a revision-checked save, waits for the durable response, and reads back the Ring’s settings. Scrolling pauses during clips and memos.

The enabled P09 controls also reveal Set up scrolling on iPhone: a reminder to save unsaved changes, the AssistiveTouch settings path, Bluetooth pairing steps, a browser swipe trial and Apple’s setup guide. Detailed setup is hidden while swipes are Off. This subsequent UI change passed 916 simulator tests; its receipts are in the app repository at build/diagnostics/p09-scroll-setup-ui-20260915/result.json. That run’s cloud test/build preflight was blocked by a separate Dex preview hash mismatch. Firmware is unchanged.

The phone’s natural-scrolling setting can reverse the visual direction. Horizontal input only applies where the app supports horizontal scrolling; it does not promise Back, Like, or tab switching. Step size and video paging need sample testing.

On iPhone: Settings → Accessibility → Touch → AssistiveTouch → Devices. Enable AssistiveTouch and connect the Ring. See Apple’s pointer-device setup. The Ring sends input directly to iOS; the design does not require Italic to remain onscreen.

Firmware behavior

  • A dedicated five-byte relative mouse report contains buttons, X, Y, Wheel and AC Pan. Buttons and X/Y remain zero; no drag or keyboard key is held.
  • The factory composite HID implementation remains untouched and uninitialized. Its report-length mismatch and incorrect pan field are not used.
  • The existing Peer Manager handles pairing and FDS initialization. HID is a P09 runtime capability; device provisioning records are not rewritten. Pairing no longer falls through into a system-attribute reset.
  • Touch input queues at most four intents and wakes the existing command worker. Intents expire after 250 ms and are invalidated by connection, security, suspend, protocol-mode or settings changes.
  • Sending requires encryption and the host’s actual notification subscription. Boot protocol, recording, disabled directions and BLE errors drop input. Sending is bounded and has no automatic retry or reconnect replay.
  • The factory links interrupt-driven BLE dispatch. Each send briefly pauses task switching and uses Nordic’s NVIC critical region to defer application callbacks while preserving SoftDevice interrupts and SVC. FreeRTOS’s BASEPRI critical section only protects queue access; it never surrounds a SoftDevice API call.
  • Existing P09 recording, battery and deletion work is included in the combined candidate. Bootloader, SoftDevice and sensor configuration stay unchanged.

The report follows USB HID usage definitions: Generic Desktop Wheel 0x38 and Consumer AC Pan 0x0238.

Settings compatibility

P09 uses controls schema 5 on 0x84 / GET 0x10 / SET 0x11. The 20-byte response and packed hold-delay/direction byte retain their layout. FDS file 0x1001, key 0x0001 uses magic 0x05435446.

Older recording and feedback preferences are preserved. Every pre-P09 swipe record is interpreted as scrolling Off in RAM; boot does not write a migration record. A schema-5 save explicitly enables phone input. Schema-4 clients may read the current mask and preserve it while changing other controls, but cannot change it.

The companion app selects schema 5 only for the exact supported P09 hardware/version. The updater permits the supported forward settings migration and blocks P09 downgrades to firmware that cannot read its record. Signed-package publication remains a separate release gate.
