P09 short recordings

A minimum saved-audio duration, owned by each Ring and controlled from its settings in the app.

Implementation host: MBP-M5 · Firmware 6.0.3.3P09 · P08 preserved

Development candidate. Software checks do not establish physical safety, recording custody on a real Ring, or a recoverable update. This work does not sign, publish, install, or flash P09.

The setting

Short recordings

Don’t delete0.5 s1 s1.5 s2 s · Default2.5 s3 s3.5 s4 s4.5 s5 s

Applies to newly completed Clips and Memos. A recording exactly at the selected duration is kept. Zero disables only duration filtering. The app enables the dropdown after a valid live P09 response and saves through the existing Save changes button.

Recording ownership

Snapshot the threshold at capture start. Count only successfully written audio, stop accepting new buffers, drain accepted packets, and close the owned file before checking deletion. The file remains unavailable to sync until finalization finishes.

Deletion uses the initial capture path and verifies absence. No older-file scan or deferred filename retry runs.

Conservative failure handling

Interrupted captures, missed buffers, failed queueing/writes, unexpected ownership, failed close, and uncertain stops cannot qualify for short-recording deletion.

A 500 ms drain timeout keeps ownership. A later stop can finish safely; microphone shutdown is idempotent. A storage failure leaves storage unavailable until recovery or restart.

Duration and storage

Duration uses the factory mono ADPCM format interpreted at 8 kHz: two PCM-equivalent samples per successfully written byte. Each half-second step is 4,000 samples. The counter saturates at five seconds and spans file rollover, so a long Memo keeps its short final segment. This measures saved audio, not time holding the sensor; hardware timing and buffer boundaries still require measurement.

New recordings use exclusive creation, so a timestamp collision cannot overwrite an existing file. Uploads open existing files read-only. Failed opens do not report success or close an unopened handle. Low space rejects new recording instead of reclaiming older files. SPI and SFUD failures reach LittleFS, and mount failure never triggers automatic formatting.
