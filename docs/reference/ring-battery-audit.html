1. How the Z62–P07 factory battery path works

  1. 1 · MeasurePower the divider; wait 10 ms; average three 12-bit ADC conversions.
  2. 2 · ConvertUse the nominal 2 MΩ / 1 MΩ divider and add 200 mV.
  3. 3 · EstimateInterpolate a fixed voltage table; filter up to ten percentages.
  4. 4 · ReportSend the battery byte over BLE; the app presents the result.
V_corrected = (average_ADC / 4096) × 3.6 V × 3 + 0.2 V
percentage = piecewise_linear_lookup(V_corrected)

The factor of three restores the nominal divider ratio. The 200 mV term is a supplier correction in the shared HARDWARE_1231_ENABLED branch used by standard 1.23.2. Neither that correction nor a cell-specific curve has measured qualification in the inspected records. Source: bc_power.c.

Between table points, firmware uses integer linear interpolation. Values above or below the table clamp to 100 or 0. These voltages are the corrected software inputs; they are not independently measured cell voltages.

Off-charger, the PMIC task normally samples and sends a percentage every 30 seconds. Active charging changes that timer to two seconds. Connection and explicit battery reads can add samples, so a ten-sample window has no fixed duration. A full window at the 30-second cadence spans about five minutes. Charge-complete sends a separate charger-state transition; it does not keep producing a percentage in that branch.

Legacy battery command 0x12 / subcommand 0 returns 0…100 when off-charger, 101 while charging, and 102 when charge-complete. Charger state is also available through subcommand 1 and the connect response. Percentage notifications and charger-state notifications are separate. Invalid 255 is supported by the experimental error path. The app normalizes these values; it does not calculate capacity independently.

Percentage also affects shutdown today. The factory PMIC task enters ship mode after four consecutive handler samples at or below 10%. Fixing the filter can change when that condition occurs even if its threshold is unchanged. Low-power behavior needs qualification alongside any battery repair.

Why 100% can persist for 30 minutes

Sampling is scheduled every 30 seconds off-charger and every two seconds while actively charging. The timer-change wrapper converts these milliseconds to RTOS ticks. Connection and explicit battery reads can add samples. A new measurement can produce the same percentage; there is no fixed interval for losing one percentage point. Charge-complete is a separate state and does not continuously sample through that branch.

The retained voltage correction can create a 100% plateau. P08 adds 200 mV before looking up the percentage, and the table clamps corrected values of at least 4,200 mV to 100%. An uncorrected software estimate of at least about 4,000 mV therefore reaches that ceiling. This is a statement about the formula, not proof of actual cell-terminal voltage or that the supplier correction is wrong. Its physical calibration remains unverified.

Smoothing alone does not account for a sustained 30-minute plateau with fresh lower samples. A check using the actual P08 filter, initialized with ten 100% samples and then fed repeated 99% samples, returns 100, 99, 99, …. At the normal cadence the change appears on the second lower sample, about one minute. The ten-sample history is roughly five minutes when samples are valid and periodic.

Freshness also needs checking. Current iOS source records batteryObservedAt but does not use it to expire the displayed percentage. The battery callback applies the firmware value directly, with no additional smoothing; foreground/device-information reads can be deferred while other transport work is active. Missed notifications can therefore leave an old value visible. A charger-state update also sets this timestamp, so a future freshness policy must track the age of the percentage measurement separately.

3. Proposed calculation and implementation order

Target meaning: estimate the fraction of usable charge remaining before the qualified recording-stop reserve, under a documented reference workload. Battery percentage must not be presented as a promise of remaining recording minutes.

Repair the factory estimator — implemented in P08

The P08 module reuses the small tested filter and error-handling concepts from the experimental path on the manifest-verified factory baseline. Its factory motor/RTOS integration is covered by the focused tests above. The requirements below describe the repair and the remaining physical checks.

  • Correct the ten-entry trimmed average. Keep only valid 0…100 samples; return unknown on failed acquisition. A failed read must never become 0%, 100%, or a valid low-battery vote.
  • Allow filtered estimates to increase after sustained recovery. Start new filter history on charger-state changes and recheck charger state after measurement; discard a batch that straddles a transition.
  • Guard one ADC transaction at a time. Exclude motor activity and batches interrupted by it. A 250 ms motor settling period and 40 µs acquisition are bench candidates, informed by existing source and Nordic guidance.
  • For the software-only baseline, retain the current correction/table and existing protection configuration. Test acquisition changes together with calibration before shipping them: fixing sampling may invalidate a correction that happened to compensate for sampling error.
  • Keep existing battery bytes and charger meanings. Test the changed filtered values against the current four-low-sample shutdown behavior on a recoverable sample.

Result: a reproducible arithmetic and recovery repair. It improves correctness but does not establish absolute state-of-charge accuracy.

Calibrate voltage and build a measured cell profile

  1. Identify the fitted cell and input circuit. CAD lists GRE170722_10, GRE170724 and GRE170726 for sizes 10–12; those names do not establish every sample’s fitted cell or electrical limits. Obtain the released cell specifications and verify the divider. Open hardware specifications.
  2. Calibrate the ADC against an external meter. Collect raw ADC values and cell-terminal voltage at several permitted voltages, with the final acquisition configuration. Fit gain and offset, then validate at voltages/units not used to fit them. Prefer one calibration per board revision only if unit spread meets the error target; otherwise store per-unit coefficients with a schema/version and integrity check.
  3. Measure charge removed. Use an external current logger during controlled full-to-reserve discharges. Integrate current to get usable mAh. Pair voltage, workload state and elapsed charge; derive monotonic lookup points. Keep a held-out unit or cycle for validation.
  4. Match the curve to the operating condition. Start with a measured steady-idle curve. Characterize continuous recording and transfer separately; use validated load-specific curves if they materially improve error. Do not label a 250 ms motor pause as fully relaxed open-circuit voltage. Unvalidated conditions carry lower confidence or become unavailable once the previous estimate expires.
  5. Version and select the profile explicitly. Tie the curve to confirmed cell/board identity. Use the supplier table as an explicitly uncalibrated compatibility fallback during development; never silently select a “calibrated” profile from a ring-size guess. Temperature adjustment requires a fitted, representative sensor and test data.
V_mV = gain_mV_per_count × median(valid_ADC_batch) + offset_mV

Q_used_mAh = ∫ I_mA(t) dt / 3600              [external reference measurement]
SOC_reference = 100 × (1 − Q_used / Q_usable)

SOC_target = interpolate(profile[cell, qualified_load], V_mV)

Q_usable is the measured charge from the specified full state to the qualified reserve endpoint in the same test. It is not a guessed nameplate capacity. Both calibration coefficients and the replacement curve remain unset until measurement.

Zero and shutdown must be designed together. The present table reaches 0% at 3.60 V, while the task shuts down at a reported 10%. The calibrated release must define a recording-stop reserve from approved cell limits, voltage sag and measured time/energy to finish a file. Do not remap the display to “0% at reserve” while leaving a shutdown rule tied to the newly remapped percentage.

Publish one stable estimate with explicit freshness

Use one firmware worker to own sampling, filtering and publication. Timer/interrupt code should request work; ADC waits and shared state updates belong outside interrupts and long critical sections. BLE reads and notifications consume the same published snapshot.

Engineering starting pointProposed behavior
SamplingEvery 30 seconds off-charger; request a new measurement after a charger transition. Take a median of five valid conversions within each batch. Confirm divider settling, ADC offset calibration and power cost on the real board.
SmoothingApply a time-based filter to the calibrated target: α = Δt / (τ + Δt), then estimate += α × (target − estimate). Start with τ = 30 seconds; keep fractional precision internally. Update once per new qualified sample, independent of phone polling frequency.
Recovery and transitionsNo permanent monotonic clamp. First valid sample initializes the filter. Reset incompatible history on charger/profile changes; after unplugging, wait for a qualified off-charger sample instead of forcing 100%. Brief invalid reads preserve the last good value internally and advance its age.
RoundingRound once to an integer at publication. A one-percentage-point hysteresis band may suppress flicker; it must not create a permanent low latch. Apply no second smoothing filter in the app.
FreshnessInitial expiry target: 90 seconds, equivalent to three normal sample periods. Stale values remain available for diagnostics but are not emitted as fresh percentages. A cached command response does not refresh the sample timestamp.
Low powerSeparate the calibrated reserve/protection decision from the cosmetic filter. Validated low voltage must bypass display smoothing and trigger graceful recording completion early enough to preserve audio. Existing PMIC/cell protection remains a final boundary.

These timing and filter parameters are proposed tuning values, not measured constants. Under a sustained step from 20% to 80%, the unsaturated filter above reaches about 79% after six 30-second samples. That mathematical example demonstrates recovery; it is not physical battery evidence.

Protocol rollout: stage one preserves 0…100 / 101 / 102 / 255. If published cached snapshots replace live reads later, add a capability-gated, versioned telemetry response with sample sequence, age, voltage, charger state, validity and calibration/profile version; choose an unused command only after a protocol allocation review. Old clients continue to receive the legacy byte, with 255 for expired/invalid estimates.

Firmware-update preflight needs stronger evidence. A cached response must not satisfy the app’s fresh-power requirement. Preserve a fresh-measurement operation, or require a new qualified sample sequence and a confirmed off-charger state before update admission. Normal display freshness is not the preflight freshness guarantee.

4. What the app should show

Keep implementation details in diagnostics. Use the same visible text, icon and accessibility semantics in Home, Devices, Ring detail and firmware preflight. Both the legacy SDK adapter and native Ring adapter must follow this policy.

5. How we prove the replacement is better

Proposed engineering acceptance targets, not achieved accuracy claims. Use the results to accept, tune or reject this voltage-based design. Do not change charge limits or lower the reserve to make the percentage appear better.

GateRequired evidence
Arithmetic / stateConstant inputs preserved; exactly one min/max removed; duplicate extrema and last-element minima; 0 and 100 endpoints; invalid samples; repeated failures; charging/charged/unplug transitions; interrupted motor/ADC batches; late callbacks and Ring switching. Regression includes both factory reproductions.
Filter behaviorNo permanent off-charger latch. A sustained qualified 20→80 step converges to within two points within 180 seconds under the proposed cadence. Stable-input display noise stays within two points. Polling faster does not change the filter time constant.
VoltageTarget maximum absolute error ≤20 mV against the external meter across the qualified operating range, on held-out voltages and units. Validate idle, recording, transfer and post-haptic conditions, including ADC calibration and temperature effects.
PercentageInitial target: 90% of qualified samples within ±5 percentage points of externally measured usable-charge reference; every qualified sample within ±10 points. Report each cell/load/temperature group separately and include the low-charge region; no pooled average hiding a failing group.
Coverage / availabilityTarget fresh numeric availability ≥95% during supported normal operation, including sustained recording and transfer. Score missing/low-confidence periods separately; meeting accuracy by suppressing most readings is a failure.
Reserve / recording custodyGraceful completion and readable saved audio before the qualified low-voltage boundary under worst supported load. Include low battery during recording, sync, haptics, charger insertion/removal and invalid sensing. Verify existing protection remains effective.
App / update101/102 never shown as percentages; “Fully charged” visible and accessible; stale readings expire; reconnect cannot cross-populate Rings; no charger-only timestamp refresh; cached samples cannot pass firmware-update preflight.
Build / physical releaseManifest-verified factory preparation, focused and existing required tests, licensed ArmCC5 build, deterministic image/provenance, and unchanged unrelated source. Physical trials require an explicitly authorized, verified target with recovery, followed by boot/version/BLE/audio readback.

Smallest useful measurement campaign

Start with at least three units for each confirmed fitted cell variant and two full-to-reserve cycles per unit at a specified room temperature/reference workload. Reserve at least one unit per variant for validation rather than fitting. Expand to continuous recording, sustained transfer, repeated haptics, partial charges, cold/warm conditions inside approved limits, and aged cells before claiming support for those conditions. This pilot estimates variability; it is not a fleet-wide reliability certification.

Log raw ADC, reference cell mV, reference current, integrated mAh, PMIC state, workload/motor state, device-reported percentage, sample sequence/age, app display/time, firmware hash, calibration/profile version and confirmed cell identity. Store test artifacts and plots with the qualification record. Omit provisioning secrets and unrelated personal data.

When hardware becomes the better answer

If the calibrated voltage approach cannot meet the accuracy and availability targets under realistic loads, evaluate a dedicated fuel gauge for a future board revision. Compare current measurement or impedance-based estimation, quiescent draw, voltage/current range, cell characterization needs, board area and BOM impact. No particular IC or fitted current sensor is assumed by this proposal.
